Agentic Engineering Workflow & Automated SDLC — Draft 2 / Final Workflow Specification
Purpose. Convert the Draft 1 agent architecture into an executable operating model across ChatGPT, Cursor, VS Code,
GitHub, CI/CD and deployment. This draft defines triggers, permissions, handoffs, retries, branch/worktree rules, automated
commits/PRs, verification gates and escalation boundaries.
Design objective. Routine implementation and ordinary engineering failures should progress through automated build,
review, repair and verification loops without requiring the operator to manually diagnose each error. Human authority
remains required for risky, ambiguous or privileged decisions.
Architect → Atlas/Cursor → Guardian + Medic → GitHub PR → Sentinel/VS Code → Watchtower +
Resolver → Harbor → CI/CD → deployment verification

Trigger A — new feature: approved product requirement, screen/flow from the Figma/177-screen map, bug/issue, or
explicit architecture task creates/updates a GitHub issue and a .vossie Feature Contract.
Trigger B — defect: CI, runtime, monitoring, QA or human report creates a defect work item with reproduction evidence
and links to the affected feature/PR.

Concurrency
Independent tasks may run in parallel using isolated branches/worktrees. Tasks touching the same migration, core contract
or high-conflict files are serialized. Atlas owns integration order. Specialists may not merge each other's work or silently edit
outside assigned scope.
Local completion gate
Before Atlas opens a PR: formatting, lint, typecheck, affected unit/integration tests and production build must pass.
Guardian then checks workflow completeness; Medic verifies execution and enters repair mode for failures.

4. Reliability loop — Guardian and Medic
Guardian audits orchestration: required tasks assigned, dependency order valid, no skipped deliverables, tests/evidence
present, contract/status updated, and Atlas has not crossed a permission boundary.
Medic owns executable health: dependency/install failures, imports, TypeScript/compiler errors, runtime exceptions, build
failures, broken API wiring and failing implementation tests.
Automatic recovery algorithm
Capture → classify → reproduce → isolate → identify owner → repair → rerun targeted check →
rerun regression subset → record evidence → Guardian re-audit.
Retry policy
Use a bounded retry budget. Default: up to 3 materially different repair attempts for an ordinary deterministic code failure.
Repeating the same unsuccessful edit does not count as progress. After exhaustion, Medic produces a structured failure
packet and escalates through Atlas/Architect or to the human boundary when required.
Failure packet
Feature/commit; failing command/test; exact error summary; reproduction steps; suspected root cause; files/components
involved; attempted fixes and outcomes; remaining hypotheses; risk of further automated changes; recommended next
action.

8. Machine-readable handoff contract
Every agent handoff should be structured rather than conversational-only. Minimum schema:
task_id  feature_id  from_agent  to_agent  repo_commit  scope  files_changed 
contracts_touched  tests_run  test_results  known_risks  open_failures  evidence_refs 
next_action  status.
Recommended .vossie workspace
architecture/ ADRs and locked technical rules; agents/ agent contracts and permissions; features/ Feature Contracts;
contracts/ API/data/event schemas; screens/ screen registry; design/ Figma/design references; security/ security
requirements; handoffs/ structured agent handoffs; status/ current feature/build/release state.
Status model
PLANNED → READY → BUILDING → CURSOR_VERIFYING → PR_OPEN → VS_VERIFYING → REPAIRING (when
needed) → MERGE_READY → MERGED → DEPLOYING → DEPLOYED → VERIFIED. BLOCKED and
HUMAN_REQUIRED are explicit terminal/holding states until the blocker is resolved.

9. Final end-to-end operating workflow
01 Intake. Requirement/design/bug enters GitHub.
02 Contract. Architect produces or validates Feature Contract and risk class.
03 Plan. Atlas reads repo state and decomposes work.
04 Isolate. Branch/worktree(s) created automatically.
05 Build. Required Cursor specialists implement in scoped parallel/serial tasks.
06 Implement-test. Probe and specialist tests execute continuously.
07 Workflow audit. Guardian checks delegation, dependencies, scope and completeness.
08 Runtime verification. Medic builds/runs and repairs ordinary failures within retry budget.
09 Integrate. Atlas integrates green tasks and reruns local completion gate.
10 Commit/push. Atomic conventional commits pushed automatically.
11 PR. PR generated with contract, risk, migration and evidence metadata.
12 Independent review. Sentinel dispatches Lens/Aegis/Vector/Pulse/Vault as required.
13 Verification audit. Watchtower confirms all current required gates executed.
14 Recovery. Resolver diagnoses failures; implementation defects route to Atlas/Medic; loop repeats.
15 Merge gate. Harbor confirms approvals and green CI; only then merges.
16 Deploy. CI/CD deploys controlled preview/staging/target release.
17 Post-deploy verification. Vector/health checks execute critical smoke paths.
18 Close. .vossie status, issue, PR, docs and release evidence update automatically.
Operating outcome
The operator should normally interact at the requirement/decision level, not as the first-line debugger. Ordinary code errors
are expected to be caught, diagnosed and retried inside the system. The workflow escalates when human authority or
judgment is genuinely required rather than pretending every failure can safely be automated away.

10. Draft 2 lock summary
Locked: Atlas and Sentinel remain separate build/control leads; Guardian + Medic and Watchtower + Resolver provide
two-layer reliability; GitHub/.vossie is shared durable state; work is branch/worktree isolated; conventional atomic commits
and PRs are automated; no autonomous direct-to-main development; mandatory CI/security/data/QA gates cannot be
bypassed; ordinary failures enter bounded repair loops; risky/privileged/ambiguous decisions escalate; deployment requires
post-deploy verification.
