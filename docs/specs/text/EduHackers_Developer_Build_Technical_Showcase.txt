Recommended delivery model

Scope: all Eduvos campuses | Build model must be validated by user research, policy, legal and payment-provider checks

Phase 1 - Web/PWA
Next.js web app. Installable from browser. Strongest speed for Hack Jam. One frontend codebase. Works on desktop and mobile.

Phase 2 - Mobile wrapper
Expo/React Native or Capacitor only after PWA flows are validated. Use if push, camera, location and app-store distribution become essential.

Phase 3 - Desktop install
PWA desktop install first. Electron/Tauri only if offline workflows, native tray, local files or richer desktop features become necessary.

Why
The project is broad: protected payments, AI moderation, reels, events, delivery and dashboards. The team needs speed, shared code and easy deployment before native complexity.

Fulfilment model: pickup, seller delivery, student courier and cross-campus fallback

Scope: all Eduvos campuses | Build model must be validated by user research, policy, legal and payment-provider checks

Campus pickup
Designated pickup zones, safe handoff points, QR/PIN confirmation, evidence timestamp.

Seller delivery
Seller handles delivery, status updates, handoff proof and delivery-fee rules.

Student courier
Verified / approved couriers, task assignment, proof-of-handoff and limited live location.

Cross-campus
Student courier between campuses, seller ships to buyer campus, or buyer collects elsewhere.

Key research question
At what point does cross-campus fallback create value, and when does it create more friction than a request/waitlist?

Proof model
Pickup code, courier scan, before/after condition photos, delivery photo, buyer confirmation and dispute evidence.

Security and privacy research requirements

Scope: all Eduvos campuses | Build model must be validated by user research, policy, legal and payment-provider checks

Object-level authorization
Every listing, order, message, dispute, evidence file, payout reference and staff dashboard query must enforce ownership and role scope.

Data minimisation
Public profiles should not reveal student number or government ID. Analytics should be pseudonymous and aggregated wherever possible.

Evidence handling
Dispute files, delivery proof and condition photos need access controls, retention rules, audit trails and safe upload processing.

Risk
Technical control

Fake seller / account takeover
verification, session security, rate limits, alerts

Payout diversion
PSP references, payout authorization, audit logs

Fraudulent disputes
evidence chain, human moderation, reason codes

AI moderation error
